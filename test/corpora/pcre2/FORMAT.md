# Pinned native observations

`inputs.json` is the argument-free observer's explicit numeric input protocol.
`observations.json` contains every event for each input, before any GregsEx
comparison. The 67 immutable contract seeds are retained under their original
IDs; their original expectations are not overwritten. New inputs cross all four
native domains, options/extras/optimizer controls, newline/BSR, callbacks,
partial/full/error outcomes, independent endpoints, imported tables, names,
iteration and substitution. `sourceExpectationId` identifies advisory frozen
seeds; `sourcePatternUnits`/`sourceMap` preserve character convenience locations.

Each case has a complete compile result and, if accepted, semantic INFO values,
decoded width-native ordered name entries, exact name-number/scan results and
callout sites. Match events have exact signed native return, defined capture
pairs, startchar and mark units; partial has only group0. A pair's start and end
are independent. `null` endpoints represent native UNSET. Callout group0 is
`null` because it is undefined during matching; pairs up to captureTop are
completed native captures. Numeric0 and empty string callouts stay distinct.
Every match callback view includes native subject units, capture_top/last,
start/current/pattern/next positions, stringoffset/units, marks, version2 flags
and signed callback return. Missing callbacks are explicit input registration
policy, not unobserved required traces.

Substitute events retain signed return, exact reported length, successful native
output units and initialized raw buffer. The raw buffer contains sentinels and
possibly source-undefined failed-output bytes; it is evidence, not a promise to
publish those bytes. Overflow required sizing includes source terminator rules.
Substitute callback events include count, initialized proposed output/range,
complete published native pairs and return. Case callback events include mode,
input/output/capacity, overlap and required size; native SIZE_MAX is `null` and
maps to the managed -1 sentinel. Error/overflow unspecified bytes are never
promoted to required outcomes. The synthetic identity/expand/abort callback
policy is explicit and independent of native built-in case mapping.

The standalone numeric observer always registers a match callback unless
callbackEnabled=false; an empty return script then means zero for every call.
Substitute callbacks register only when substituteCallbackEnabled=true. These
policies are explicit in this versioned protocol because source-only fixture
empty arrays were never complete observations. The source pcre2test protocol
retains its own unmodified callback implementation/scripts in the upstream lane.

`upstream-accounting.json` indexes every native-dispatched source recipe/control
and every106original testdata member, with per-field exclusions/preconditions.
It references exact event ranges/native-output byte ranges in
`native-evidence.tar.gz`. The instrumented reference decoder retains original
source units, effective options, compile results/semantic INFO, matching inputs,
independent captures and full callbacks. Its human-readable native output is
validated against exact pinned golden output by the same RunTest selfcheck as
the unmodified driver. Direct cross-driver file comparison was initially unavailable
because RunTest deletes its output; missing raw files are now retained before
cleanup, with original structured traces preserved. Original source bytes/licenses/per-member hashes are retained
by the pinned contract archive; no Python decoder replaces native input decoding.
The Windows-localized source recipes are executed with their original bytes;
unavailable host locale errors remain explicit. EBCDIC/32/JIT/DFA/physical
layout and conversion/tooling exclusions never become generic syntax errors.

`controls.json` classifies every long modifier, short alias and #-command from
pcre2test's actual source table. Mixed recipes keep logical syntax/matching and
observable fields required while excluding only the named native fields. Source
NO_UTF_CHECK invalid-input observations and malformed continuation after UTF
\\C are retained as source-undefined, with source-supported reasons. Defined
split-unit captures and subsequent caller-supplied bad UTF offsets stay distinct.

This is correctness evidence from a development oracle. It establishes no
GregsEx implementation, parity, allocation, throughput, new RID or NativeAOT
claim. Native physical counter equality and exact human messages remain excluded.

C048 discloses the published `test/corpora/pcre2/C048-erratum.md` input repair:
only the intended success invocation's pairCapacity changes1→2. The frozen seed,
original explicit1pair -54 observation, explicit2pair success and NULLauto-full
success all remain. Native error reportedLength2 is not successful output.
`upstream-recipes.jsonl.gz` contains every per-recipe record; the compact
`upstream-accounting.json` holds counts/member/table identities and its hashes.

UTF validation errors preserve native errorOffset/get_startchar, per pcre2api.3:3370–3380. Marks use the preceding native unit as payload length, preserving binary NUL. markDefined identifies success/no-match/partial; other error marks remain undefined. Upstream getter supplements retain original pre-supplement raw traces.
