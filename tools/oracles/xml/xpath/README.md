# Fixed XPath oracle procedures

Run from the repository root. These are development-only fixed procedures with no argument parsing, no product library forwarding, and no timing/allocation counters. `prepare.py` constructs source expectations and normalizes standalone literal QT3 calls; it never reads GregsEx outputs. The original QT3 suites remain unchanged. `qualify.py` checks every artifact/source hash and audits actual Saxon table resources against retained Unicode16 rows. `replay.py` invokes the real processor and compares all structured results; `verify.py` can recheck retained results without an installed processor.

Use Java 25 (actual intake: Temurin25.0.2+10 on macOS arm64). Set `GREGSEX_XPATH_JAVA_HOME` to its JDK directory, and `GREGSEX_XPATH_ORACLE_CACHE` to an external artifact directory; defaults are the actual intake's `/Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home` and `/private/tmp/gregsex-xpath-intake`. Download the four exact URLs in `test/corpora/xml/xpath/processor-lock.json` into that directory using their recorded names. Qualification rejects changed bytes. The pinned processor is SaxonJ-HE12.5 (MPL2.0) with xmlresolver5.2.2 and its data JAR (Apache2.0); binaries are external development inputs, never GregsEx package assets. Public immutable Maven URLs and full hashes make the inputs reacquirable; this repository does not claim permanent binary retention. Source JAR is used only to audit the API/implementation, not on the execution classpath.

```sh
python3 tools/oracles/xml/xpath/prepare.py
python3 tools/oracles/xml/xpath/replay.py
dotnet run --project tools/oracles/xml/xpath/SchemaCheck/SchemaCheck.csproj -c Release --no-restore --disable-build-servers -p:UseSharedCompilation=false
dotnet test/GregsEx.Tests/bin/Release/net10.0/GregsEx.Tests.dll --filter-namespace 'GregsEx.Tests.Conformance.Xml.XPath' --minimum-expected-tests 5 --fail-skips on --fail-warns on --no-ansi
```

`Replay.java` selects XQuery3.1, explicit XML1.0/XSD1.1, Saxon's XPath regex engine, no `!j`/Java-native syntax, default Saxon optimizer, and a512MiB JVM ceiling. It uses s9api XQuery evaluation for all function jobs and the original QT3 expressions; QT3 assertions are evaluated against bound typed values, preserving any-of/all-of. Nodes compare using deep-equal; namespace identity survives prefix differences. `XML-C043` alone uses `Configuration.compileRegularExpression(...,"XP30/XSD11",...)`, checks `isPlatformNative()==false`, and uses `RegexIterator.analyze/processMatchingSubstring` to obtain the otherwise disallowed empty-matching capture pattern. Segment iteration has a10000 ceiling; process execution has60-second timeouts. No measured latency is recorded.

Numeric UTF16 output serialization retains empty strings, CR/LF and supplementary units. Analyze nodes are translated into the frozen preorder tree; text/group ranges count original UTF16 units or explicitly mapped UTF8 bytes. Unmatched capture slots are padded distinctly from matched-empty. UTF8 oracle subjects are explicitly decoded to XDM codepoints for comparison and ranges mapped back; this is an adapter, not proof of a native UTF8 processor API. Three standard typed string functions plus AnalyzeString remain UTF16. Domain/budget policies outside XDM are marked source-only and never counted as external processor passes.

The external processor supplies FORX namespace/code but does not provide original pattern/flag/replacement UTF16 offsets. New/imported diagnostic fixtures mark the whole implicated original argument (including its empty boundary); their coordinate comparison is **argument provenance**, not a claim that Saxon emitted that offset. Integration must compare FORX code/namespace and argument domain, require the real diagnostic's native unit and bounds to be valid in that original argument, and run its parser's precise-coordinate assertions separately. Per-case diagnosticPolicy distinguishes this envelope from exact frozen or source-derived spans. The36 frozen contract seeds retain their exact coordinate recipes unchanged. See `annotations.json`; `comparison.json` compares external errors only by code/namespace and reports native successful ranges/trees exactly.

Processor disagreements are not successful equalities. Each disposition in the corpus register freezes the observed typed result and retains the target expectation; replay rejects a new unregistered observation. Source-only/skipped results are reported separately. Stage evidence proves corpus/provenance/processor intake. Actual GregsEx conformance, limits, AOT and measurements remain the integration/gate tasks.
